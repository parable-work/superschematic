The shop keeps its users, their sessions, its products and its stock in
Postgres. `shop-db` declares those tables once; superschematic writes the
DDL, a typed Go data-access layer, and the row types in Go and TypeScript.

## Configure a DB service

<Snippet file="schemas/services/shop-db/schema.config.ts" />

A DB schema always gets its SQL and its Go ORM. `outputs.types` adds the
row types in the languages it lists; the ORM uses the Go ones.

## Declare the tables

Every class in a DB schema is a table. Start with the columns every table
shares, and the people who use the shop:

<Snippet file="schemas/services/shop-db/src/shop.schema.ts" symbol={['Auditable', 'User']} />

- `extends Auditable` copies `createdAt` and `updatedAt` into `User`. A
  class that other tables extend is not a table itself.
- `@key` marks the primary key. `AutoGenerate<Identity.UUID>` lets the
  database generate it, so a new row has no id until it is inserted.
- `@unique` adds a unique constraint.
- `Nullable<T>` makes a column nullable. Every other column is `NOT NULL`.
- The scalar decides the column type: `Contact.Email` is `CITEXT`, so
  email addresses compare case-insensitively, and `Identity.Name` is
  `VARCHAR(80)`.

A session belongs to a user:

<Snippet file="schemas/services/shop-db/src/shop.schema.ts" symbol="Session" />

`Relation<User, { onDelete: "CASCADE" }>` stores a `user_id` column with a
foreign key to `user`, and deletes the user's sessions with the user. The
`session` auth provider looks sessions up by `jti` when it authenticates a
request to the Go API.

Then the catalog:

<Snippet file="schemas/services/shop-db/src/shop.schema.ts" symbol={['Product', 'StockLevel']} />

`Default<boolean, true>` is a default for decoders, not for the database:
when a JSON or YAML payload leaves `inStock` out, the generated Go and
TypeScript decoders fill in `true`. The column itself has no SQL default.

## The ORM

`orm/shop-db` is the Go module `example.com/acme/orm/shop-db`, built on
pgx. Each table gets a repository:

<Snippet file="testdata/generated/orm/shop-db/interfaces.go" symbol="ProductRepositoryInterface" />

- `orm.Connect(ctx, databaseURL)` opens a pool and returns a `*Database`.
  `GetProductRepository()` and its siblings hand out repositories, and
  `Transaction` runs a function with repositories bound to one transaction.
- `FindMany` takes a `ProductFilter` with one filter per column, such as
  `InStock: &orm.BoolFilter{Eq: &inStock}`, and `ProductFindOptions` for
  the columns to read, the order and the page. It returns the rows and the
  total count of matching rows. Its options must name at least one column:
  `orm.ProductFields{}.All()` reads them all.
- `CreateOne` leaves out a zero id and `createdAt`, so the database fills
  them in, and returns the inserted row.
- A lookup that finds nothing returns `orm.ErrNotFound`.
- `orm.NewNoOpDatabase()` implements the same interfaces without a
  database: lists are empty, a lookup is not found, and a create returns
  its input. The tests in the next parts run against it.
