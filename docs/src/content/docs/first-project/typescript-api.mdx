Shoppers fill carts on the storefront, which the shop runs on TypeScript.
`shop-storefront` declares the cart routes. superschematic generates a
router, built on [Hono](https://hono.dev), that decodes, validates and
gates each request, and a TypeScript SDK to call it. You write the
handlers and say who the caller is.

## Declare the API

<Snippet file="schemas/services/shop-storefront/src/carts.schema.ts" />

- `CartLine` and `CartView` use `Price` from `shop-common`. A schema that
  imports another service's types lists that service in its config's
  `dependencies`.
- `@requirePermission` puts a route behind the auth gate: the caller must
  hold one of the listed permissions. `@publicRoute` opens `getHealth` to
  anyone.
- `Validate<number, { min: 1; max: 99 }>` bounds the quantity. The router
  checks it on every request, and the SDK checks it before sending.

## Configure it

<Snippet file="schemas/services/shop-storefront/schema.config.ts" />

`language: "TYPESCRIPT"` generates the router package instead of a Go
module. The router validates requests with the TypeScript types, so
`types` lists TypeScript.
`ShopCommon` is the handle `shop-common`'s build wrote to its
`src/service.generated.ts`, imported from `@acme/shop-common` as a schema
imports types. A config imports nothing else but
`@superschematic/schema-config`.

## Implement the routes

The router asks for one implementation per operation set, keyed by the
set's namespace:

<Snippet file="testdata/generated/api/shop-storefront/interfaces.ts" symbol={['CartImplementation', 'Implementations']} />

Each method receives its decoded arguments and a request context, and
returns the view, or an `OperationResult` to choose the status. The
implementation is a package of its own at the naming file's
[`[implementation_paths]`](/superschematic/reference/naming/#implementation_paths)
default, `typescript/shop-storefront`, which `shop-stack`'s build
scaffolded once. It exports `create`, which builds the implementations
from the API's `Deps`, and `authenticate`, which builds the end-user check
from them; `examples/acme-shop/typescript/shop-storefront/index.ts` keeps
carts in memory:

<Snippet file="typescript/shop-storefront/index.ts" symbol={['authenticate', 'create', 'cart']} />

- `authenticate` returns the caller as a `Principal` (`subject` and
  `permissions`) or `null`. The router reads the bearer token into
  `ctx.bearerToken` for it. A route that needs a caller answers 401
  without one and 403 when no permission covers the route's; `carts`
  covers `carts.read` and `carts.write`.
- `Deps` holds what the server gives the implementation: here only a
  logger, since the storefront has no database, no settings and no API to
  call. The generated `Constructor` and `AuthenticatorFactory` types hold
  `create` and `authenticate` to it.
- Before a method runs, the router has decoded `cartId` as a UUID and
  parsed the body with the generated parser, so a bad UUID or a quantity
  of 100 answers 400 without reaching your code.
- A thrown `notFound(...)` or `HttpProblem` answers with an RFC 9457
  problem body. `errorHandler()` and `notFoundHandler()` answer the same
  way for errors outside the router.
- A success answers `{ "data": <view>, "meta": { "requestId": ... } }`.

## Call it from TypeScript

The SDK's `fetch` option replaces the network, so the example's test
mounts the router over the implementation, as the server's entrypoint
does, and hands each request straight to the Hono app:

<Snippet file="typescript/shop-storefront/index.test.ts" symbol={['storefrontApp', 'sdkFor']} />

<Aside>
  The SDK sends `auth.token` as `Authorization: Bearer <token>`, which
  `authenticate` reads as `ctx.bearerToken`. The config sets neither
  `public` nor `authDb`: they wire the Go server's auth provider to its
  stores, and this router reads no store.
</Aside>

Then each namespace is a property of the SDK, and each method takes the
route's arguments:

<Snippet file="typescript/shop-storefront/index.test.ts" from="test('a shopper adds lines" to="  });" />

The SDK parses each response with the generated parser, so `updatedAt`
arrives as a `Date`. A response outside 2xx throws an `ApiError` with its
`statusCode`, or `AuthenticationError` for 401, and an input the
generated validator refuses throws `ValidationError` before any request.

## Install the packages

Until the packages are published, a service resolves the generated
packages and the runtime from the checkout. The runtime ships compiled
JavaScript, so `scripts/check.sh` first runs `bun install` and
`bun run build` in `runtime/http/typescript`.
`schemas/dist` is a Bun workspace of every generated TypeScript package,
whose root overrides the runtime and superscalar with the checkouts the
naming file's `[paths]` names. Every package under `typescript/` joins it
too ([TypeScript](/superschematic/install/typescript/#serve-a-generated-api)):
the storefront's implementation, and `typescript/clients`, the example's
clients and type tests. So `bun install` there links
`@acme/shop-storefront-types` to `@acme/shop-common-types`, the router
and the SDKs to the packages they import, and the implementation to the
router, with nothing linked by hand:

```sh
cd schemas/dist && bun install
```

Then run the tests from `examples/acme-shop/typescript`:

```sh
bun test
```

The generated packages ship TypeScript sources, so run them with Bun, a
bundler or a TypeScript loader.

## Run it in the stack

`shop-stack` deploys the storefront on a server of its own. The stack's
build writes the server's entrypoint, `server/shop-stack/shop-storefront`
in the output root: a `package.json` in the same workspace, a Dockerfile,
and a `main.ts` that builds the storefront from its `Deps` and serves it
with [Bun](https://bun.sh):

<Snippet file="testdata/generated/server/shop-stack/shop-storefront/main.ts" from="// shop-storefront: its implementation" to="app.onError(errorHandler());" />

It answers `/healthz` and `/readyz` beside the API's routes, listens on
`$PORT`, and drains on SIGTERM. `superschematic stack dev` installs the
workspace and runs it with `bun main.ts`, beside the Go servers;
[Stacks](/superschematic/guides/stacks/#the-acme-shops-stack) walks the
stack, and `go/stack_dev_test.go` reads a cart from the running
storefront.
