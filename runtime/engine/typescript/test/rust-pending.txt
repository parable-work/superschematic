# The engine's test files that do not pass yet on the Rust engine through its
# Node-API addon (ENGINE_IMPL=rust; D58, milestone 7). scripts/rust-ratchet.mjs
# runs each test file so under Node.js and Bun: a file that fails and is not
# listed fails the run, and so does a listed file that passes, so the list
# only shrinks. A line is a file under test/, then the runtimes it is pending
# on when not both (node, bun), then why.
#
# Milestone 7a runs the engine's synchronous API over the addon, with a policy
# or a permission matcher written in TypeScript asked on the JavaScript
# thread, and the TypeScript HTTP and MCP adapters over it. What the files
# below wait for, the first named on each line first:
#
#   bridge     a behavior written in TypeScript (defineBehavior,
#              behaviors.register) or an id source (ids): the test-only
#              JavaScript behavior bridge (7b)
#   storage    raw SQL on the engine's file (engine.storage), which the
#              identity routes' store takes too (7b)
#   watch      events.watch over the engine's notifier, which the event
#              stream waits on (7b)
#   validator  schemas.validator, which returns the TypeScript SchemaValidator
#              (7b)
#   json       a value JSON cannot carry (NaN, a Date) reaches the Rust engine
#              as another
#
# Milestone 7b also brings engineApp and engineMcp as Hono adapters over the
# engine's own routes (api::handle), a mount's tool filter and onError, and
# openEngineAsync beyond the basic async call. No test that runs here fails
# on what the Rust engine does; the tests behind the bridge have yet to run.
